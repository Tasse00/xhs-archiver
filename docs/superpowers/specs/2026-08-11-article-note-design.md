# 文章 Note 设计

## 1. 目标

采集者可以在采集小红书图文文章时按需记录一段多行纯文本 Note，并在之后通过侧边栏或数据集浏览页继续修改。

Note 属于文章，不属于某次归档或某个采集者。一篇文章在仓库里只有一份 Note；重采、接管和迁移都必须保留它，除非使用者明确修改或清空。

## 2. 范围

本次包含：

- 首次采集时填写可选的多行纯文本 Note
- 在侧边栏读取、添加、修改和清空已归档文章的 Note
- 在数据集浏览页读取、添加、修改和清空 Note
- 更新、接管和迁移时正确保留或替换 Note
- 以独立文件保存 Note，并保持适合人工阅读和 Git diff 的稳定格式

本次不包含：

- Markdown 渲染
- 多条 Note、Note 历史或评论线程
- 按采集者区分个人 Note
- Note 的修改人、修改时间等额外元数据
- 在浏览页中搜索、筛选或排序 Note
- 跨设备草稿同步
- 插件关闭后恢复尚未保存的草稿

Git 提交记录已经能够追踪文件的修改人和时间，因此本次不在 Note 文件中重复记录审计信息。

## 3. 方案选择

采用文章目录下独立的 `note.txt`：

```text
collected/<note_id>/
├── note.json
├── note.txt          # 可选，文章级人工备注
├── comments.json
└── images/
```

未采用把 Note 放入 `note.json` 的方案，因为独立修改一句备注不应重写包含大块 `raw` 数据的 JSON，也不应让重采流程承担额外的字段合并风险。

未采用 `annotation.json`，因为本次只需要多行纯文本。结构化包装和审计字段没有当前使用场景，只会增加人工编辑成本。

## 4. 文件语义

- 文件名固定为 `note.txt`，编码为 UTF-8。
- 文件不存在表示文章没有 Note。
- 只包含空格、制表符或换行的输入同样视为没有 Note。
- 写盘时把 `CRLF` 和单独的 `CR` 统一为 `LF`。
- 非空文件末尾固定保留一个换行；界面读取时不把这个格式化换行显示成额外空行。
- 除换行规范化和末尾换行外，不修改使用者输入的正文内容。
- 清空后保存会删除 `note.txt`，而不是保留空文件。

`note.txt` 是可选附属文件，不加入“指针存在意味着文章数据完整”的质量判据。旧文章没有该文件时自然兼容，无需迁移 `note.json` schema 或索引格式。

## 5. 核心模块

新增聚焦于 Note 文件操作的核心模块，例如 `src/core/article-note.ts`。它不接触 React 或 Chrome API，只依赖现有的 `ReadStore` / `Store` 接口。

模块职责：

- 定义固定文件名
- 规范化待写入文本
- 从文章目录读取 Note
- 写入或替换非空 Note
- 输入为空时删除 Note 文件

读取结果必须区分：

- 文件不存在：成功返回空内容
- 文件存在：成功返回正文内容
- 真正的文件系统错误：向调用方抛出，不能降级成空内容

这样可以防止读取失败被误判为“没有 Note”，随后又用空值覆盖仓库中的原内容。

## 6. 归档接口与生命周期

归档选项增加 `noteText?: string`，三种取值的语义固定为：

- `undefined`：使用者没有修改 Note，保留已有内容
- 非空字符串：使用新内容写入或替换 `note.txt`
- 空字符串或纯空白字符串：使用者明确清空，删除 `note.txt`

不能用空字符串同时表达“未编辑”和“清空”，否则重采会误删旧 Note。

### 6.1 首次采集

侧边栏将当前文本框内容随归档请求传入。文章主体和图片写入后、索引指针写入前，归档核心写入非空 `note.txt`，或清理目标目录中可能由失败重试遗留的旧 `note.txt`。

如果使用者填写了非空 Note 但文件写入失败，本次归档不能显示成功，也不能写入新的索引指针。已写入的文章目录可以作为安全的孤儿目录留待重试。

### 6.2 原位更新

- `noteText === undefined` 时完全不碰已有 `note.txt`。
- 传入字符串时才替换或清空 Note。
- Note 写入失败时不删除已有索引；界面明确提示文章数据可能已经更新，但 Note 未保存。

### 6.3 接管

接管只改变归档归属和索引指针，不改变文章级 Note。默认继承已有 `note.txt`；使用者在本次操作中主动编辑时才替换。

### 6.4 迁移

迁移必须在删除旧目录前处理 Note：

1. 若 `noteText === undefined`，先读取旧目录的 `note.txt`；不存在则视为空。
2. 若使用者主动编辑，采用传入的新值。
3. 在新目录写入或清理 `note.txt`。
4. 完成文章数据和新索引写入后，才删除旧目录。

旧 Note 读取失败或新 Note 写入失败时，迁移失败并保留旧目录。

### 6.5 独立修改

侧边栏和浏览页都可以直接调用核心模块保存 Note，不经过文章归档流程。独立修改不得改变：

- `archive_count`
- `first_archived_at` / `last_archived_at`
- 采集者
- 索引指针
- `note.json` 或 `comments.json`

删除整篇文章时，现有逻辑递归删除文章目录，`note.txt` 会自然一并删除。

## 7. 侧边栏交互

在文章信息卡下方、采集记录之前增加“Note（可选）”区域。编辑器位于可滚动主体内，不占用固定底部动作区。

### 7.1 新文章

- 显示多行纯文本框。
- 显示“将在采集文章时一并保存”的提示。
- 不提供单独保存按钮，因为文章目录尚不存在。
- 点击“采集这篇”时提交当前内容。
- 归档失败后保留文本框内容，方便直接重试。

### 7.2 已归档文章

- 根据当前权威指针路径读取 `note.txt`。
- 编辑后显示“保存修改”和“取消”。
- “保存修改”只操作 `note.txt`；“取消”恢复最近一次成功读取或保存的内容。
- 若直接点击更新、接管或迁移，尚未保存的修改也随本次操作提交。
- 保存成功后提供轻量反馈；失败时保留编辑内容并显示原因。

### 7.3 草稿与并发状态

- 侧边栏本次生命周期内，以 `note_id` 保存未提交草稿；切换文章再切回来时仍可继续编辑。
- 关闭侧边栏后不保证恢复未保存草稿。
- 读取 Note 期间显示加载状态，不允许用默认空值保存。
- Note 保存、文章归档、迁移或删除期间，禁用其他会写入同一文章目录的动作，避免并发写盘。

## 8. 浏览页交互

在详情栏的文章正文与作者信息之间增加 Note 区域。

- 有内容时默认按纯文本展示并保留换行，提供“编辑”入口。
- 没有内容时显示“暂无 Note”和“添加”入口。
- 编辑状态提供“保存”和“取消”。
- 保存期间禁用重复保存及当前文章的删除动作。
- 保存失败时保持编辑状态和输入内容，并展示具体原因。
- 保存成功后更新展示值，不重新加载整篇 `note.json`。

浏览页的列表扫描仍只读取 `note.json`。只有打开文章详情时才额外读取该目录的 `note.txt`，因此本次不会让全库扫描为每篇文章增加一次文件读取，也不会把 Note 加入现有搜索索引。

如果使用者在插件外直接修改 `note.txt`，重新打开该文章详情或重新读取当前页面后应取得磁盘上的最新内容；本次不做文件实时监听。

## 9. 错误处理

- 文件不存在按空 Note 处理，其他读取错误必须提示。
- 保存失败时不更新“已保存内容”，输入框内容不能丢失。
- 首次归档的非空 Note 写入失败时，不写新索引指针。
- 更新已有文章时 Note 写入失败，不删除旧索引，并明确说明文章数据和 Note 的实际状态。
- 迁移过程中 Note 读取或写入失败，不删除旧目录。
- 权限失效、仓库目录消失等情况复用现有 File System Access 错误分类和恢复入口。
- 成功提示必须在写盘 Promise 真正完成后出现。

多文件归档无法获得文件系统级事务。现有顺序继续保证破坏性动作最后执行，并让中断残留落在可识别、可重试的一侧。

## 11. 自动化测试

### 11.1 核心模块

- 文件不存在返回空内容
- 非空文本换行规范化后写入
- 替换已有内容
- 空白内容删除文件
- 读取错误不被转换成空内容
- 写入和删除错误向调用方传播

### 11.2 归档流程

- 首次采集写入 Note
- 首次采集空 Note 不留文件，并清理失败重试遗留文件
- 原位更新未编辑时保留 Note
- 原位更新主动替换 Note
- 原位更新主动清空 Note
- 接管默认继承 Note
- 迁移默认复制 Note
- 迁移时采用主动编辑的新内容
- Note 读取或写入失败时不删除旧目录、不写错误的新指针

### 11.3 侧边栏

- 新文章 Note 随采集提交
- 已归档文章正确读取 Note
- 独立保存、清空和取消
- 更新或迁移时提交未保存修改
- 按 `note_id` 保留当前侧边栏生命周期中的草稿
- 失败后输入内容不丢失
- 写入期间正确禁用冲突动作

### 11.4 浏览页

- 空状态与已有内容展示
- 添加、编辑、取消、保存和清空
- 保存失败时保留编辑状态
- 只在详情打开时读取 Note
- Note 不参与搜索、筛选和排序

自动验证命令：

```bash
npm test
npx tsc --noEmit
npm run build
```

## 12. 真实浏览器验收

真实浏览器验收由使用者执行，覆盖：

1. 首次采集时填写 Note，确认 `note.txt` 内容和格式。
2. 首次采集留空，确认没有空文件。
3. 原位更新未编辑 Note，确认内容不变。
4. 从侧边栏独立修改和清空 Note。
5. 从浏览页添加、修改和清空 Note。
6. 接管他人文章，确认原 Note 被继承。
7. 迁移文章，确认 Note 到达新目录且旧目录被删除。
8. 制造权限失效或目录消失，确认输入不丢且提示方向正确。
9. 在磁盘上直接编辑 `note.txt`，重新打开后确认读到最新内容。

自动化测试和构建通过只能证明代码路径与类型正确，不替代 File System Access API 在真实 Chrome 中的最终验收。
